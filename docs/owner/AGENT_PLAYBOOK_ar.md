# دليل المالك: كيف تشغّل وكيل Arena Agent Mode على مشروع Nile وتحصل على أفضل نتيجة

**لمن هذا الدليل:** لك أنت يا محمد، كصاحب المشروع. لا يحتاج أي خبرة تقنية.
**الفكرة:** كل ما عليك هو **نسخ رسالة جاهزة من هذا الدليل ولصقها للوكيل**، ثم مراجعة ما يسلّمه بقائمة تحقق بسيطة.
**مكان هذه الملفات الآن:** الفرع `docs/unified-plan-2026-10-19` على GitHub. بعد أن توافق وتدمجه في `main`، احذف السطر رقم 0 من رسالة البداية.
**المرجع:** المراحل والمزايا في [`docs/PRODUCT_PLAN.md`](../PRODUCT_PLAN.md)، والمهام بالترتيب في [`docs/STATUS.md`](../STATUS.md) §5.

## 1) ما الذي يستطيعه الوكيل، وما الذي لا يستطيعه

**يستطيع:**
- قراءة الكود وكتابته.
- تشغيل الاختبارات وتشغيل قاعدة بيانات تجريبية.
- البحث في الإنترنت.
- كتابة التقارير والملفات.
- رفع الكود إلى GitHub، إذا أعطيته صلاحية.

**لا يستطيع (أو ممنوع عليه):**

| الحد | المعنى العملي لك |
|---|---|
| يعمل داخل «صندوق» مؤقت (sandbox) | أي شيء لم يُرفع إلى GitHub قد يضيع عند إعادة تشغيل البيئة. **اطلب منه دائمًا أن يرفع عمله في نهاية المهمة** |
| لا يملك صلاحية على GitHub من نفسه | يحتاج منك «توكن» مؤقتًا لكل جلسة رفع (§5) |
| لا يتذكر المحادثات القديمة بالتفصيل | لهذا كل المعلومات محفوظة في المستودع، وأول رسالة تقول له أين يقرأ |
| ممنوع أن يقرر بدلًا منك في أمور العمل | سيعرض عليك خيارات بأزرار، فاختر أو اكتب رأيك |

## 2) القواعد الذهبية الست

1. **مهمة واحدة في كل مرة.** لا تكتب «اعمل كل المشروع». اختر مهمة من §4.
2. **ابدأ كل محادثة جديدة برسالة البداية** (§3).
3. **لا تقبل كلمة «تم» بدون دليل.** الدليل = رقم commit، ورابط على GitHub، ونتائج الاختبارات بالأرقام.
4. **أنت وحدك توافق على:** الرفع إلى GitHub، والدمج في `main`، والنشر، وحذف أي شيء، وأي قرار فلوس أو صلاحيات.
5. **التوكن مؤقت دائمًا:** يوم واحد، ولمستودع واحد، ثم تلغيه بنفسك بعد انتهاء المهمة.
6. **إن شككت في شيء، اطلب تحقق وكيل ثانٍ** (§6).

## 5) كيف تعطي الوكيل صلاحية GitHub بأمان (خطوة بخطوة)

1. **افتح صفحة التوكنات:** ادخل GitHub، واضغط صورتك أعلى اليمين، ثم **Settings**، ثم (أسفل القائمة) **Developer settings**، ثم **Personal access tokens**، ثم **Fine-grained tokens**، ثم **Generate new token**.
2. **Token name:** مثلًا `nile-agent-2026-10-20`.
3. **Expiration:** اختر تاريخ الغد.
4. **Repository access:** اختر **Only select repositories**، ثم `nilesys` فقط.
5. **Permissions → Repository permissions:**
   - **Contents: Read and write** ← دائمًا.
   - **Pull requests: Read and write** ← فقط إذا كانت المهمة فتح PR.
   - **Workflows: Read and write** ← فقط في مهمة CI.
6. **انسخ التوكن والصقه للوكيل** عندما يطلبه.
7. **بعد انتهاء المهمة احذفه:** نفس الصفحة، ثم اختيار التوكن، ثم **Delete**.

> ⚠️ **التوكن الذي استخدمته يوم 2026-10-19 كانت صلاحيته admin. إن لم تحذفه بعد، احذفه الآن.**

## 6) كيف تراجع ما سلّمه الوكيل (دقيقتان)

**قائمة التحقق:**
- [ ] هل ذكر **رقم commit** (7 حروف أو أكثر) واسم الفرع؟
- [ ] هل أعطاك **رابطًا** على GitHub يفتح فعلًا؟
- [ ] هل كتب نتائج الاختبارات **بالأرقام**، مثل «236/236 على PostgreSQL 17»، وليس فقط «كله نجح»؟
- [ ] هل ذكر **ما لم يُنجز** وما لم يُتحقق منه؟
- [ ] هل طلب موافقتك قبل الرفع أو الدمج أو الحذف؟

**رسالة تحقق مستقل (أعطها لوكيل في محادثة جديدة):**
```

شغّل الاختبارات المذكورة على PostgreSQL حقيقي وقارن الأرقام. لا تعدّل شيئًا ولا ترفع شيئًا.
قل لي بوضوح: صحيح / غير صحيح / غير قابل للتحقق، ولماذا.
```

## 7) علامات خطر: أوقف الوكيل فورًا إذا

- قال «تم» أو «جاهز للإنتاج» بلا رقم commit ونتائج.
- طلب توكنًا قديمًا، أو بحث عن كلمات سر في الملفات.
- عدّل `main`، أو دمج، أو نشر، أو حذف فرعًا، بلا موافقتك.
- حذف اختبارًا أو عدّله «لكي ينجح».
- قرر بنفسه في قرار فلوس أو صلاحيات.
- خلط مشروعًا آخر (مثل Jiwdah أو TerraNex) داخل Nile.

**اكتب له:** «توقف. اشرح ما فعلته بالضبط، بالأدلة، ولا تنفّذ أي شيء آخر.»

## 8) نصائح للحصول على أفضل نتيجة

- **محادثة جديدة لكل مرحلة كبيرة:** المحادثات الطويلة جدًا تجعل الوكيل يختصر ما سبق. كل شيء محفوظ في المستودع، فلا خوف من البدء من جديد.
- **اطلب منه أن يسألك بأزرار** عندما يحتار. هذا أسهل لك من الكتابة.
- **اطلب لقطات شاشة** لأي واجهة قبل الموافقة عليها.
- **إذا لم تفهم شيئًا، اكتب:** «اشرحه بمثال من محل حقيقي.»
- **لا تلصق كلمات سر أو بيانات عملاء حقيقية** في المحادثة. التوكن المؤقت فقط، ثم احذفه.

## 9) قاموس سريع

| الكلمة | معناها |
|---|---|
| مستودع (repository) | مكان الكود على GitHub |
| فرع (branch) | نسخة عمل منفصلة، لا تؤثر على الأصل حتى تُدمج |
| `main` | النسخة الرسمية. لا تتغير إلا بموافقتك |
| commit | «حفظة» لها رقم مثل `0207c13`، وهي الدليل على التغيير |
| PR (طلب دمج) | طلب لإدخال فرع في `main`، تراجعه وتوافق عليه |
| CI | فحص آلي على GitHub يشغّل الاختبارات مع كل تغيير |
| staging | نسخة تجريبية على الإنترنت قبل الإنتاج |
| migration | تغيير في شكل قاعدة البيانات |
| توكن (token) | مفتاح مؤقت يسمح للوكيل بالرفع إلى GitHub |
| محرّك (engine) | «عقل» النظام: الحسابات والقواعد، بدون شاشات |

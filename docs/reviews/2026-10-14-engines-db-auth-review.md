# Review: engines ↔ database integration, auth, permissions, tenant isolation

> **Status: HISTORICAL (note added 2026-10-14).** Reviewed `main` after PR #1 and PR #2 (`0811ae0`); its
> findings (F-n) were addressed by PR #3. An independent, overlapping review of the same commit is
> [`0001-nile-engines-db-auth-review.md`](0001-nile-engines-db-auth-review.md) (H-n). Live status of every
> open finding is kept only in [`docs/STATUS.md`](../STATUS.md) §6.

- **Date:** 2026-10-14
- **Scope:** everything merged in PR #1 (engine cores) and PR #2 (DB layer),
  reviewed before building the first operational path (login → saved sale).
- **Method:** every suspected defect was reproduced with a failing probe on
  real PostgreSQL (PGlite) *before* it was fixed; every fix is pinned by a
  test that asserts the exact PostgreSQL error code; the end-to-end suite was
  mutation-checked (bugs planted on purpose must make tests fail).

## Findings

| # | Severity | Finding | Evidence | Fix |
|---|---|---|---|---|
| F1 | **Critical** | Cross-tenant FK hole: tenant A could insert a `transaction_lines` row pointing at tenant B's sale. PostgreSQL checks foreign keys **without** applying RLS. | Probe: insert succeeded as `nile_app` with tenant A context. | `UNIQUE (tenant_id, id)` on parents + **composite FKs** `(tenant_id, parent_id) → (tenant_id, id)` on every child (9 FKs). Test 3c asserts SQLSTATE `23503`. |
| F2 | High | Money columns were `integer` (int4): any amount ≥ 21,474,836.47 EGP overflowed. | Probe: `integer out of range` at 30M EGP. | All money columns `bigint`; app enforces `Number.isSafeInteger`. Test stores 30,000,000.00 EGP exactly. |
| F3 | High | Hand-written SQL migration contradicted ADR-0004 ("migrations generated by Drizzle Kit") and had already drifted from the Drizzle schemas (missing uniques in TS). | Diff of schema vs SQL. | Schemas are the single source; `drizzle-kit generate` produced `0000_nile_engines.sql`; RLS policies declared in TS (`pgPolicy`). The unapplied hand-written file was removed (never deployed anywhere). |
| F4 | High | Sale contract accepted `unitPriceMinor` from the client (customer-set prices). | `createSaleSchema` in PR #2. | Prices loaded from the catalog server-side; contracts are `.strict()` — unknown keys (price, total, tenantId) ⇒ 400. |
| F5 | High | Engines were not connected to persistence at all (no service layer); `withTenant` had never executed against a database. | Code inspection. | `recordSale`/`getSale`/`listCatalog` services; `withTenant` re-typed for Drizzle and covered by invariants 4 + 5. |
| F6 | Medium | RLS on the tenant registry (`organizations`) would have blocked Better Auth, which must resolve memberships **before** a tenant context exists. | Design review vs ADR-0005 §2. | Tenant = Better Auth `organization`. Identity/membership tables are platform-global (no RLS, accessed only by the auth module + server-side resolver); all 14 business tables are under RLS. |
| F7 | Medium | Runtime/migration role split (ADR-0005 §7) existed only inside a test. | Code inspection. | `0001_security_hardening.sql` creates `nile_app` (NOSUPERUSER, NOBYPASSRLS), grants + default privileges, `FORCE RLS` on every RLS table; the app **refuses to start** if its effective role can bypass RLS. |
| F8 | Medium | Boolean flags stored as text `'true'/'false'`. | Schema. | Native `boolean`. |
| F9 | Low | Sale lines stored only an item id — receipts would change if a product were renamed. | Schema. | Name snapshots (`name_ar`, `name_en`) on each line. |
| F10 | Test gap | The first e2e suite did **not** catch "server trusts a client-sent tenant header" (mutation M3 survived). | Mutation run: 22/22 still green with the bug planted. | Added header/query tenant-spoofing test; M3 now fails the suite. |
| F11 | Ops | First boot crashed when the PGlite data folder did not exist (tests always used a fresh temp folder). | Live server start. | `openPglite` creates the folder. |

**Deferred (tracked, not blocking this path):** DB-level no-double-booking
(`EXCLUDE USING gist`) lands with the booking flow; Nx + pnpm workspace
(ADR-0001) still pending — the repo runs on npm for now; daily demo reset job;
delegated permissions (starting 0079).

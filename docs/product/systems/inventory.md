# نظام المخازن — مواصفة مستقلة

## 1) الغرض في سطر

الرصيد الصح في اللحظة الصح: كل وحدة دخلت أو خرجت لها سطر وسبب، والقيمة على الرف معروفة.

## 2) المستخدمون

| المستخدم | يدخل بـ | يقدر يعمل | لا يقدر |
| --- | --- | --- | --- |
| مدير مخزن | `manager` (نظام المخازن) | تسوية · توريد · موردون · قراءة الأصناف | البيع أو فتح وردية كاشير |
| أمين مخزن | `store` | قراءة · توريد · طلب تسوية | التسوية بدون مدير |
| الكاشير | — | لا يدخل هذا النظام | كل الشاشات |

## 3) الشاشات

| الشاشة | ماذا فيها |
| --- | --- |
| لوحة المخزن | عدد الأصناف · قيمة المخزون بالتكلفة · تحت حد الطلب · آخر الحركات |
| الأصناف | الرصيد · حد الطلب · التكلفة · قيمة الرصيد · تصدير |
| تحت حد الطلب | ما يجب توريده والكمية المقترحة |
| حركات المخزون | كل حركة: الوقت · الصنف · الفرق · الرصيد بعدها · النوع · من فعلها |
| الموردون والتوريد | موردون · مستحقات · توريد يحدّث متوسط التكلفة |

## 4) نموذج البيانات

| المجموعة | الحقول |
| --- | --- |
| `products` | نفس كتالوج الكاشير — مخزون واحد لا اثنان |
| `stockMovements` | `productId` · `qty` · `reason` · `kind` · `after` · `note` · `userId` |
| `suppliers` | `id` · `name` · `phone` · `note` |
| `purchases` | `supplierId` · `items[{productId, qty, cost}]` · `total` · `paid` |

## 5) الواجهات

```
GET  /api/products                 ← قراءة فقط لمستخدم المخزن
GET  /api/stock/low
GET  /api/stock/movements?productId=&limit=
POST /api/stock/adjust             { productId, qty, reason }
GET|POST /api/suppliers
GET|POST /api/purchases            { supplierId, items[], paid }
GET  /api/export/stock.csv
```

## 6) القواعد

1. المخزون لا يصبح سالباً أبداً → 409 مع رسالة مفهومة.
2. كل تعديل يكتب حركة تحمل السبب والرصيد بعده.
3. التوريد يحدّث متوسط التكلفة المرجح: `(رصيد×تكلفة + كمية×سعر) ÷ الرصيد الجديد`.
4. مستخدم نظام آخر لا يقرأ مسارات الكاشير، ومستخدم الكاشير لا يعدّل مخزوناً من هنا.

## 3) تعارضات صريحة تُسجّل ولا تُحسم انفراديًا

1. **ADR-0001 + خطة المنتج §5 يقولان: الكاشير تطبيق Next.js**، بينما الإنتاج الحالي
   واجهة Vanilla تخدم من الـAPI نفسه، ومهمة المالك هنا «Product UI Refactor لا إعادة
   هندسة». **القرار المتخذ ضمن التفويض:** تطوير `apps/web` الحالية كما هي تقنيًا، وتسييج
   التعارض هنا. الانتقال إلى Next.js يحتاج ADR جديدًا يحل محل/يحدّث ADR-0001 جزئيًا
   وقرار مالك — **مُحال للمالك** (انظر الفجوات G-14).
2. **D-C (من يغلق الوردية؟) وD-D (من يرى التقرير؟) مفتوحان** في خطة المنتج. الخادم
   الحالي: الإغلاق بـ `sale:create` والتقرير بـ `sale:read` (الكاشير عنده الاثنان).
   الواجهة الجديدة **لا تخترع سياسة خادمية**: تعرض التقارير والمرتجع في قسم «إدارة»
   يُظهَر فقط لمن لديه `sale:void` (صلاحية المدير الفارقة في العقد الحالي) كطبقة UX
   فوق الخادم — والحماية الحقيقية تبقى خادمية، وحسم D-C/D-D بصلاحية تقرير مستقلة
   فجوة Backend (G-12/G-13) تحتاج قرارك.
3. **أرقام «المعروض» مقابل «المعتمَد»:** إجمالي السلة قبل البيع حساب عرض من أسعار
   الكتالوج التي أعادها الـAPI — يُوسم صراحةً «مبدئي — يُحتسب نهائيًا عند الحفظ»،
   والرقم المعتمد بعد البيع هو ما يعيده المحرك فقط (إجمالي + دفعات + باقٍ). هذا
   مبدأ `financial-correctness` و`FINANCIAL_RULES.md` ولا يُستثنى منه الباقي.

## 4) نظام التصميم (Phase B) — «نيل» التجاري

**الاتجاه:** SaaS مؤسسي هادئ، عربي أولًا RTL، كثافة معلومات منظمة، ضجيج بصري أدنى.

### الهوية والرموز (Tokens في `apps/web/styles.css`)
- لون علامة واحد: أخضر نيلي عميق `#0E7A5F` (فاتح) / `#2FBF9B` (داكن) — يحمل «النيل» دون زخرفة.
- محايدات بسلّم رمادي مزرقّ، أسطح متدرجة `bg → surface → surface-2`، حدود واحدة.
- دلالي: نجاح/تحذير/خطر/معلومة بقيم ثابتة لكل ثيم؛ لا لون خام خارج الرموز.
- خط: **IBM Plex Sans Arabic** (400/500/600/700، subsets عربي+لاتيني، مستضاف ذاتيًا
  في `apps/web/fonts/` برخصة OFL-1.1 المرفقة — يعمل دون شبكة خارجية) مع سلسلة
  احتياط نظامية. أرقام لاتينية `ar-EG-u-nu-latn` + `tabular-nums` للأسعار.
- مقياس: مسافات 4pt، أنصاف أقطار (8/12/16)، ظلان فقط، خطوط 12→28 بدرجات ثابتة.
- ثيم فاتح أساسي + داكن اختياري (`data-theme`) يُحفظ محليًا؛ `prefers-reduced-motion` محترم.
- أيقونات SVG خطية مرسومة داخل الملفات (24px) — صفر Emoji تشغيلي.

### المكونات الموحدة
أزرار (أساسي/ثانوي/شبح/خطر/أيقونة ≥44px)، حقول بتسميات ظاهرة وأخطاء مرتبطة، بطاقات
أصناف، شرائح فئات، صفوف سلة بعدّاد كمية، جداول، حوارات (`<dialog>` أصلية بحبس تركيز)،
تنبيهات (Toast + بانر)، شارات حالة (وردية/مخزون/دور)، هياكل تحميل، حالات فارغة بإجراء تالٍ.

### هيكل التطبيق (Shell)
ترويسة ثابتة: شعار/اسم المحل (من `/me`) ← تنقّل (البيع/الوردية/الإدارة*) ← شارة وردية ←
مستخدم ودور بالعربية ← ثيم/خروج. على الجوال: شريط سلة سفلي ثابت (عدد+إجمالي+دفع)
والسلة درج سفلي (Bottom Sheet) — لا تكديس لسطح المكتب. (*الإدارة بصلاحية فقط.)

- **البيع (افتراضي):** بحث مثبت أعلى الأصناف (تركيز تلقائي، `/` للوصول، Enter على SKU
  مطابق تمامًا = إضافة قارئ باركود كلوحة مفاتيح)، فئات من الكتالوج، سلة جانبية/
  درج جوال، دفع بحوار مخصص يدعم الدفع المقسّم الحقيقي.
- **الوردية:** بطاقة حالة كاملة (فتح برصيد، متوقع خادمي عند الإغلاق، تأكيد قبل الحفظ،
  نتيجة فرق واضحة).
- **الإدارة (sale:void):** تقرير بنطاق تاريخ بعنوان «صافي المحصّل» (ADR-0014) +
  مفوتر/محصّل/مرتجعات/معلّق مفصولة + تفصيل طرق الدفع، وبطاقة «استرجاع فاتورة برقمها»
  ومرتجع جزئي مثبت بتأكيد. ما لا يدعمه العقد يُعرَض كفجوة موثقة لا كزر وهمي.

### قواعد سلامة الواجهة (ملزمة في التنفيذ)
1. كل عملية مالية لها **هوية عملية معلّقة واحدة**: مفتاح + بصمة حمولة؛ يعاد استخدامها
   عند: ضغط مزدوج، قطع شبكة، 5xx، انتهاء جلسة ثم إعادة دخول. تُرمى فقط عند نجاح
   مؤكد أو رفض نهائي موثّق (4xx غير 401). الأزرار تُقفل أثناء الطيران.
2. لا `innerHTML` لنصوص قادمة من الخادم — بناء DOM بـ `textContent` فقط.
3. الفلوس صحيحة (قروش) من الطرف للطرف: تحويل إدخال المستخدم بمحلّل نصّي عشري
   (يدعم أرقامًا عربية ٠-٩ وفاصلة ٫)، وتنسيق العرض بتفكيك صحيح دون قسمة عائمة،
   وكمية السلة بأجزاء الألف الصحيحة (milli).
4. السلة لا تُمسح عند أي خطأ قابل للاستعادة؛ تُحفظ بذاكرة الجلسة (sessionStorage
   بالمتغير+الكمية فقط) وتُستعاد بعد إعادة التحميل/الدخول، وتُتحقق أسعارها من كتالوج جديد.
5. الواجهة فوق الخادم: الإخفاء UX فقط؛ كل إجراء محكوم أصلًا بصلاحية خادمية.
6. لا بيانات تجريبية ولا حسابات افتراضية في واجهة العميل — البريد حقل حر وكلمة المرور فارغة.

# Nile Systems — منصة الأنظمة والمواقع الجاهزة (نسخة تعليمية)

> **Status: HISTORICAL (English note, 2026-10-14).** This documents the plain-Node prototype as of
> 2026-10-13. Paths such as `/home/user/nilesys` and backup archives refer to a local machine and are not in
> this repository. Statements about "current" behaviour, plans or stack choices describe the prototype only,
> not Nile's production path. See [`prototypes/README.md`](../README.md) and
> [`docs/STATUS.md`](../../docs/STATUS.md).

منصة موحّدة على غرار `marketing-app.runasp.net` (ديمو كود ماتريكس): موقع تسويقي يعرض أنظمة إدارة ومواقع جاهزة، مع **ديمو حقيقي شغال** — نفس تجربة الأصل: حسابات تجربة بضغطة واحدة، بيانات حقيقية بتتحفظ، عربي/إنجليزي بتبديل كامل.

> **الفرق الجوهري عن الموقع الأصلي:** هنا الكود مفتوح بالكامل وبني بأبسط تقنية ممكنة تشتغل فوراً — **Node.js خالص بدون أي مكتبات خارجية** (zero npm dependencies). مفيش `npm install`، ومفيش قاعدة بيانات خارجية: البيانات في ملف JSON واحد سهل الاستبدال بـ SQLite/MySQL لاحقاً.

## التشغيل

```bash
cd nilesys
node server.js          # → http://localhost:3000
```

## اللي شغال دلوقتي (المرحلة 1)

- **الصفحة الرئيسية** (`/`): هيرو + إحصائيات + منتقي النشاط (اقترح نظام وموقع حسب شغلك) + كروت الأنظمة السبع + المواقع السبعة + قسم برامج الويندوز + جدول مقارنة (أونلاين/ويندوز) + تبديل عربي/إنجليزي كامل مع RTL.
- **نظام الكاشير** (`/systems/pos.html`):
  - دخول بحسابات تجربة بضغطة (صلاحيات مدير/كاشير)
  - نقطة بيع: بحث + مسح باركود + أقسام + شبكة أصناف + سلة كاملة + خصم + كاش/فيزا + فاتورة بإيصال قابل للطباعة
  - فواتير: عرض ومراجعة أي فاتورة
  - مرتجعات (للمدير): اختيار صنف وكمية، المرتجع الجزئي والكلي، ورجوع المخزون
  - ورديات: فتح وردية بنقدية أول المدة، وإغلاق بعدّ الدرج وحساب الفرق
  - تقارير: مبيعات وربح النهارده/الأسبوع، متوسط الفاتورة، الأكثر مبيعاً، مبيعات بالساعة، توزيع طرق الدفع
  - أصناف (للمدير): إضافة/تعديل/حذف مع هامش الربح والمخزون
  - هوية المحل: اسم المحل واللوجو واللون الأساسي (بيتغير فوراً في كل الشاشات)
  - إعادة ضبط الديمو (زي «بيرجع لأصله يوميًا»)

## ملاحظات

- الديمو «حي»: أي بيانات بتعملها بتتحفظ في `data/db.json` فعلاً. اضغط «رجّع بيانات الديمو» من شاشة الهوية (مدير) أو امسح الملف وهيعيد البذور تلقائياً.
- عربي/إنجليزي: الزر في أعلى أي شاشة، والاختيار بيتحفظ في المتصفح.
- الأرقام بالإنجليزي (Latin digits) زي الموقع الأصلي، والعملة `ج.م` / `EGP` حسب اللغة.
- المشروع تعليمي توضيحي: التسجيل والصلاحيات مبسّطان (مناسب للديمو، مش production auth).

## النشر على Vercel (مُهيَّأ، وغير منشور بعد)

النسخة دي جاهزة للنشر كـ **Vercel project جذره `prototypes/nilesys`** — بدون أي مكتبات وبدون خطوة build:

| الملف | وظيفته |
|---|---|
| `api/[...path].js` | يوجّه كل `/api/*` إلى نفس `requestListener` الموجود في `server.js`. **صفر منطق هنا** — ملف واحد للحقيقة. |
| `vercel.json` | إعدادات الدالة فقط (512MB، 10 ثوانٍ). |
| `public/` | يخدمها Vercel تلقائياً كملفات ثابتة. |

تغييرات في `server.js` لازمة للسيرفرلس (كلها مشروطة، ولا تغيّر السلوك المحلي):

1. **لا يفتح بورت عند الاستيراد**: `if (require.main === module) start();` — فالاختبارات و`node server.js` كما هما.
2. **الجلسة موقَّعة (HMAC) ووافرة بذاتها**: كل طلب على Vercel قد يصل لنسخة (instance) مختلفة، فالتوكن لازم يتحقق بنفسه بدل ذاكرة العملية. التحقق صار `timingSafeEqual`، وتسجيل الخروج يلغي `jti` داخل النسخة الواحدة.
3. **مسار البيانات**: على Vercel يكون `DB_FILE = /tmp/nilesys-db.json` (النظام غير قابل للكتابة إلا `/tmp`).

### القيد الحقيقي — لازم يُقال بوضوح

`/tmp` **لكل نسخة على حدة** وليس مشتركاً. النتيجة على Vercel:

- تسجيل الدخول والصلاحيات والتقارير: تعمل في أي نسخة (التوكن موقَّع).
- **البيانات** (المبيعات، الأصناف، الوردية): تعيش داخل النسخة الدافئة، وتعود لبذور الديمو عند بدء نسخة جديدة.

فالديمو على Vercel يصلح للعرض والمراجعة، ولا يصلح كدليل على «البيانات بتتحفظ» — الإصرار على ده يحتاج قاعدة بيانات مشتركة (Supabase/Postgres) بدل ملف JSON.

### متغيّرات البيئة المطلوبة

| المتغيّر | القيمة |
|---|---|
| `SESSION_SECRET` | أي نص عشوائي طويل — وإلا استُخدم المفتاح الافتراضي المكتوب في الكود (مقبول للديمو فقط). |
| `DB_FILE` | اختياري على Vercel (الافتراضي `/tmp/nilesys-db.json`). |

## تخزين مشترك حقيقي (Supabase/Postgres) — يعالج قيد `/tmp`

بدل ما الديمو يعتمد على ملف داخل النسخة، فيه **مخزن مشترك اختياري**: نفس مستند JSON كما هو يُحفظ في
**صف واحد** في جدول `demo_state` على Supabase. مفيش تغيير في شكل البيانات ولا في منطق التطبيق.

| المتغيّر | الغرض |
|---|---|
| `SUPABASE_URL` | `https://<ref>.supabase.co` |
| `SUPABASE_SERVICE_KEY` | مفتاح `service_role` — **سرّي، للسيرفر فقط، لا يُوضع في المتصفح أبداً** |
| `DEMO_STATE_ID` | اختياري (افتراضي `nilesys-demo`) — يسمح بأكثر من مستند/بيئة على نفس الجدول |

بدون المتغيّرين، السلوك كما هو تماماً (ملف محلي) — الاختبارات لا تتأثر.

### الجدول (منشأ فعلاً في مشروع `nilesys-demo`)

```sql
create table public.demo_state (
  id text primary key,
  doc jsonb not null,
  updated_at timestamptz not null default now()
);
alter table public.demo_state enable row level security;
revoke all on public.demo_state from anon, authenticated;
```

**RLS مفعّل ولا توجد أي policy** — مقصود: `anon` و`authenticated` لا يستطيعان قراءة أو كتابة أي شيء،
و`service_role` فقط يتجاوز RLS. يعني البيانات مش مكشوفة حتى لو المفتاح العام (publishable) تسرّب.
